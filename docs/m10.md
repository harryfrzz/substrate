# M10: macOS workspaces

A macOS workspace is a macOS Sequoia VM on an EC2 Mac in Singapore, with a
terminal in the browser like any other workspace. Macs are shared: each runs
up to two workspaces' VMs, the most Apple's licence allows. A new Mac is
started only when every Mac is full, after you agree to its cost, and released
once it has been empty past the 24 hours AWS bills it for at least.

The remote desktop (Screen Sharing through noVNC) isn't built yet; workspaces
have terminals only.

## What it costs

A `mac2.metal` dedicated host (an M1 Mac mini) in `ap-southeast-1` is $0.779 an
hour, billed for 24 hours at least: about $18.70 a start. The UI shows this,
and starts nothing, until you press **Start a new Mac**. A workspace on a Mac
that's already running costs nothing more.

| Limit | Default | Setting (control box) |
|---|---|---|
| Macs at once | 2 (the account's quota, and a cap on cost) | `SUBSTRATE_MAX_MACS` |
| macOS workspaces per user | 1 | `SUBSTRATE_MAX_MAC_WORKSPACES_PER_USER` |
| VMs per Mac | 2 | Apple's licence; not a setting |
| Each VM | 4 cores, 6 GB (of the M1's 8 and 16) | `SUBSTRATE_MAC_VM_CPUS`, `SUBSTRATE_MAC_VM_MEMORY_MB` (macd) |

## How it works

```
browser ──HTTPS/WSS──▶ CloudFront ──▶ control box (Mumbai)
                                        │  pool of Macs, in SQLite
                                        │  EC2 API calls to ap-southeast-1
                                        ▲
              WSS, dialled out by macd  │
                                        │
EC2 Mac (Singapore): macd ── tart ── macOS VM ×2 (softnet)
                              └── ssh -tt into each VM for terminals
```

- **The pool** (`apps/control/src/macs/`). A new workspace goes to a free slot
  on a Mac that's up or on its way, the fullest first so the others empty out.
  With no free slot, it allocates a dedicated host (trying each AZ in turn) and
  starts a macOS instance on it. Every minute it releases any Mac that has been
  empty for 10 minutes and allocated for 24 hours, and gives up on one that
  hasn't connected within 90 minutes.
- **macd** (`apps/macd`), on each Mac as `ec2-user`, runs the VMs with tart and
  dials the control box at `/api/macs/agent` over the public URL, so a Mac needs
  no open port. It reconnects by itself. Requests (create or delete a VM, list
  or open terminals) go down that WebSocket as JSON. For a terminal, macd dials
  back a second WebSocket, and the control box pairs it with the browser's.
- **A new Mac** runs `images/mac/setup-mac.sh` at first boot (from its user
  data). The script grows the disk, installs tart and softnet, pulls the base
  image (`ghcr.io/cirruslabs/macos-sequoia-base`), and starts macd as a
  LaunchDaemon. That takes 15 to 30 minutes. `bun run deploy:control` uploads
  both macd and the script, so a new Mac gets the current ones. **A running Mac
  keeps the macd it started with.**
- **A new VM** is cloned from the base image (copy-on-write, so it's quick),
  booted, and locked down over SSH before anyone uses it:
  - macd's own key goes in, and password sign-in is turned off (and checked).
  - The VM gets host keys of its own, and a random password in place of the
    image's public one.
  - Claude Code is installed if it can be.

## Security

- Each Mac's agent has its own token, made at allocation and stored only as a
  hash. It's accepted only while that Mac is booting or ready.
- The token reaches the Mac in its user data. The instance metadata service
  answers only the Mac itself: IMDSv2 with a hop limit of 1, so its VMs can't
  read the token or the Mac's credentials.
- softnet keeps each VM away from the other VM and from the Mac's network. The
  Macs' security group lets nothing in.
- The Mac's role can only read `mac/*` in the artifacts bucket. The control box
  can create Mac hosts and instances only in `ap-southeast-1`, and terminate or
  release only ones tagged `substrate:mac`.
- macOS workspaces need sign-in, and users see only their own.

## Setting it up

1. **Quota.** Ask for `mac2` dedicated hosts in `ap-southeast-1` under Service
   Quotas, "Running Dedicated mac2 Hosts". The pool's default cap is 2.
2. **CDK in Singapore**, once: `cd infra && bunx cdk bootstrap aws://<account>/ap-southeast-1`.
3. **`bun run deploy:infra`** deploys both stacks:
   - the Mac network (`SubstrateMac`: a VPC with public subnets in 1a and 1b,
     and a security group with no inbound)
   - the Mac role and instance profile
   - the control box's permissions
   - `/substrate/public-url`
4. **`bun run deploy:control`** gives the control box the URL Macs dial, and
   uploads macd and the setup script. The **macOS workspaces** panel appears
   once this is done.

## When something's wrong

Sign in to a Mac with Session Manager (`aws ssm start-session --region
ap-southeast-1 --target <instance>`):

| What | Where |
|---|---|
| First-boot setup | `/var/log/substrate-setup.log` |
| macd | `/var/log/substrate-macd.log`, and `sudo launchctl print system/dev.substrate.macd` |
| VMs | `tart list`, and `~/.substrate-macd/logs/<workspace>.log` as `ec2-user` |

The control box logs each allocation and release as `macs: …`. A Mac it lost
track of can be found by its tag, `substrate:mac=host`, in the EC2 console's
Dedicated Hosts.
